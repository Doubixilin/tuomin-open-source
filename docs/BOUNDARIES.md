# 能力范围和安全边界

## 最小示例能证明什么

合成示例证明：已声明的实体和合同编号能被替换；同一段脱敏文本能逐字回填；未知占位符被拒绝。
它不使用 NER、云端模型、HTTP 服务、个人文档、磁盘映射或系统钥匙串。

它不能证明开放文本中的所有敏感内容都被发现。实际效果取决于规则覆盖、词典质量、模型能力、输入格式和策略。

## 不可忽略的边界

- 图片与扫描 PDF 不提供 OCR；不能把“读取到的文字已处理”说成“整个文件已脱敏”。
- 文档嵌入对象、修订、批注等内容必须按解析能力和阻断结果处理。
- 模型未就绪要区分必需检测器失败与可选检测器降级；不得把降级伪装成完整检测。
- `egress_allowed=true` 只表示当前配置与扫描通过，不是零漏检承诺。
- 代理只覆盖实际经过本网关的请求；其他连接器、插件和直连流量不自动受保护。
- 提示注入规则属于检测辅助，不能把不可信输入提升为指令。

## 映射、回填与运行数据

映射包含原值。最小示例只放在内存；离线 CLI 的 `save_mapping` 则会显式写出明文 JSON，必须作为敏感本地文件管理。
服务路径：macOS 默认使用钥匙串密钥与 AES-GCM，Windows 使用当前用户 DPAPI，Linux 当前有明文开发存储路径。不要把 Linux 当前实现用于需要静态加密保证的环境。
`TUOMIN_ALLOW_PLAINTEXT_STORE=1` 仅供合成测试／开发，不能作为生产修复方案。

回填只应发生在可信本地显示或恢复流程。不要把原文、映射、Token 或恢复材料提交到 Git、Issue、截图或外部模型。
社区源码无需商业激活，但 HTTP 管理 Token 和 API 能力权限仍然必须按接口要求配置。

## 部署范围

默认监听 `127.0.0.1`。本仓库不承诺可直接用于公网或多租户服务。生产使用前需验证自己的访问控制、数据留存、加密、日志与威胁模型。
